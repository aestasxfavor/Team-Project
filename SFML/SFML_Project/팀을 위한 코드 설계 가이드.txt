 💻 코드 작성 기본 가이드 (ver. 팀 통합)

✅ 협업 및 병합 효율을 위해 모든 구성원이 아래 스타일을 기준으로 작성하는 것을 권장합니다.

✅ 1. 변수명 작성 규칙
- 변수명은 소문자로 시작
- 두 단어 이상은 카멜케이스(camelCase) 사용

ex)
int count;
float enemySpeed;
std::vector<int> waveList;

✅ 2. 클래스 이름
- 클래스 이름은 대문자로 시작 + 카멜케이스

ex).
class Player;
class EnemyManager;
class StarManager;

✅ 3. 함수 이름
- 함수도 소문자로 시작 + 카멜케이스
- 동사형으로 작성 (기능이 드러나게)

ex).
void update(float dt);
void draw(sf::RenderTarget& target);
void handleInput();
bool isDead();

✅ 4. 멤버 변수 초기화
- 초기화는 가급적 생성자 이니셜라이저 리스트로 작성

- .h에 반드시 멤버 변수를 선언한 뒤, .cpp에서 초기화(생성자로 초기화할 경우에는 cpp에서 생성자 초기화라고 주석 달기)

ex).
// .h
class StarManager 
{
private:
    Player* player;

public:
    StarManager(Player* p);
};

// .cpp
StarManager::StarManager(Player* p)
    : player(p)
{}

✅ 5. include 순서
- 공통 유틸 헤더인 #include "Util.h" 사용하기 (기본세팅용)
- 해당 클래스의 .h

ex).
#include "Util.h"
#include "Player.h"

✅ 6. 클래스 분리 기준
- 클래스는 한 가지 역할만 담당 (단일 책임 원칙)

ex). Player가 공격, 카메라, 드랍까지 다 하지 않도록

✅ 7. 테스트 코드도 기준대로
- 테스트라도 구조는 실제 코드 기준으로 작성
- main.cpp에 기능 몰빵 ❌
- 클래스 나누고 update/draw 함수 따로 정의할 것

✅ 8. 함수 정의 위치
- 헤더에서는 선언만 (정의는 .cpp에 작성)

ex).
// .h
void update(float dt);

// .cpp
void Player::update(float dt) { ... }

✅ 9. 코드 설명 방식
꼭 필요한 함수, 클래스에만 간단한 주석


// ⭐ 플레이어가 별을 먹는 거리 판정
bool canCollect(const sf::Vector2f& starPos);

✅ 10. 병합 전 체크
역할 분리된 구조로 돼 있는지 확인

전역변수/싱글톤 사용 자제

ex). Player, Camera, Weapon 등 기준 구조 안 맞으면 병합 보류될 수 있음

💡 이 가이드는 병합/협업을 위한 기준이며, 지켜지지 않으면 병합이 어려울 수 있습니다.
